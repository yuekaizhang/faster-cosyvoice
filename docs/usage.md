# Faster CosyVoice Usage Guide

English | [简体中文](usage_zh.md)

## Online inference

Online requests can include reference audio directly, or register a voice on
the server once and reuse it by name.

### Zero-shot voice cloning

`stream_client.py` encodes a local reference-audio file into the request:

```bash
uv run --frozen python examples/stream_client.py \
  --ref-audio ref.wav \
  --ref-text "The exact transcript of the reference audio." \
  --target-text "This is the text to synthesize." \
  --out speech.wav
```

### Register and reuse a voice

Voices are cached in the server process and must be registered again after a
restart:

```bash
uv run --frozen python examples/register_voice.py \
  --url http://127.0.0.1:8000 \
  --name demo \
  --ref-audio ref.wav \
  --ref-text "The exact transcript of the reference audio."
```

After registration, send a streaming request using the voice name:

```bash
uv run --frozen python examples/stream_client.py \
  --url http://127.0.0.1:8000 \
  --voice demo \
  --target-text "Hello, this speech was generated by Faster CosyVoice." \
  --out speech.wav
```

You can also register a sample selected from a Hugging Face dataset:

```bash
uv run --frozen python examples/register_voice.py \
  --name benchmark \
  --dataset yuekai/seed_tts_cosy2 \
  --split test_en \
  --index 0
```

List the voices registered in the current server process:

```bash
curl http://127.0.0.1:8000/v1/audio/voices
```

### HTTP API

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/health` | Process health check |
| `GET` | `/ready` | Model and warm-up readiness check |
| `GET` | `/v1/models` | List the currently loaded model |
| `GET` | `/v1/audio/voices` | List registered voices |
| `POST` | `/v1/audio/voices` | Register a voice |
| `POST` | `/v1/audio/speech` | Generate speech |

Primary fields for `POST /v1/audio/speech`:

| Field | Description |
|---|---|
| `input` | Required target text |
| `voice` | Registered voice; mutually exclusive with `ref_audio + ref_text` |
| `ref_audio` | Data URI, HTTP(S) URL, or path local to the server |
| `ref_text` | Exact transcript of the reference audio |
| `response_format` | `wav` or `pcm`; defaults to `wav` |
| `stream` | Whether to stream the HTTP response; defaults to `false` and does not change the backend pipeline |
| `seed` | Sampling seed; defaults to `42` |

Send a non-streaming request with a registered voice:

```bash
curl http://127.0.0.1:8000/v1/audio/speech \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "faster-cosyvoice",
    "input": "Hello from Faster CosyVoice.",
    "voice": "demo",
    "response_format": "wav",
    "stream": false
  }' \
  --output speech.wav
```

`stream=false` only makes the server buffer the complete audio before sending
the response. The LLM and Token2Wav stages still execute in streaming chunks;
this option does not switch to the static-batch offline inference path below.

`response_format=pcm` returns raw little-endian PCM16. Streaming WAV responses
use an unknown-length WAV header. The server always outputs mono audio at
24 kHz.

## Offline inference

Run a single sample:

```bash
uv run --frozen python examples/offline_inference.py \
  --ref-audio ref.wav \
  --ref-text "Reference text" \
  --target-text "Target text" \
  --output-dir results/single
```

Run batched inference over a dataset:

```bash
uv run --frozen python examples/offline_inference.py \
  --dataset yuekai/seed_tts_cosy2 \
  --split wenetspeech4tts \
  --batch-size 8 \
  --output-dir results/wenetspeech4tts
```

Each dataset row uses its own `prompt_audio` and `prompt_text`. The output
directory contains WAV files, `input_manifest.jsonl`, `expected.json`,
`run_config.json`, and `metrics.json`.

Common ablation options:

```bash
# Disable DSpark
--draft-model none

# Use Torch Flow
--flow-estimator torch
```

## Performance configuration

### Streaming chunks and CUDA Graphs

The recommended configuration uses the default `15 → 30 → 60…` speech-token
hops and enables bucketed CUDA Graphs for streaming Flow and HiFT. Add one
server option to use the built-in, validated bucket presets:

```bash
--streaming-cuda-graph
```

Batch-size-1 offline Flow has a corresponding one-switch option:

```bash
--offline-flow-cuda-graph
```

`--speaker-encoder-tensorrt` affects only the frontend for uncached reference
audio. A registered voice does not rerun the speaker encoder for every
request. Graph buckets are captured lazily on their first use, so production
deployments should warm up with requests whose shapes resemble real traffic.

### Advanced configuration: custom CUDA Graph buckets

Normal deployments do not need to specify buckets. Override the presets only
when the request-length distribution is materially different or when padding
and memory use need to be tuned. All three advanced options use equivalent
audio duration in seconds; the CLI converts them to Mel frames internally.
Speech tokens run at approximately 25 Hz and Mel features at 50 Hz, so one
Mel frame represents 20 ms. For example, `1.28` seconds is exactly 64 Mel
frames; these fractional values come from frame-rate conversion rather than
estimation.

An input is padded up to the first bucket that can contain it. Inputs longer
than the largest bucket fall back to eager execution. Denser buckets reduce
padding but increase graph-capture time and memory use. When overriding the
presets, cover common request shapes and make the largest bucket long enough
for the expected tail of the workload.

Advanced bucket options can be used independently to enable CUDA Graphs for
only one module, or combined with the one-switch preset. An explicitly
specified bucket list overrides the preset for that module; unspecified
modules keep their built-in presets.

A Flow bucket covers the full context, including the prompt and potentially
lookahead and padding. It is not simply the duration of newly generated
audio.

| Option | Duration represented | Applies to |
|---|---|---|
| `--offline-flow-graph-bucket-seconds 8,12,16,20,24` | Complete prompt + generated Flow context | Offline Flow with Token2Wav batch size 1 |
| `--streaming-flow-graph-bucket-seconds 10.24,12.8,15.36,17.92,20.48,25.6` | Full Flow context including prompt, padding, lookahead, and consumed tokens | Single-session streaming Flow |
| `--streaming-vocoder-graph-bucket-seconds 1.28,2.56,3.84,5.12,7.68,10.24` | Current HiFT input-audio duration | Non-final streaming HiFT chunks |

### Leading-silence trimming

Enable `--trim-leading-silence` to reduce audible TTFA. It trims silence from
the beginning of the PCM stream delivered to the player, but does not reduce
model computation or model-side TTFP.

### Core options

The table below lists the built-in CLI defaults.

| Option | Built-in default | Purpose |
|---|---:|---|
| `--gpu-memory-utilization` | `0.5` | vLLM memory budget; leaves memory for Token2Wav and DSpark |
| `--draft-model` | `yuekai/cosyvoice3_llm_dspark` | Pass `none` to disable speculative decoding |
| `--streaming-flow-estimator` | `flashinfer` | Can fall back to `torch` |
| `--token2wav-batch-mode` | `packed` | Torch Flow supports only `serial` |
| `--token2wav-batch-size` | `8` | Maximum packed sub-batch size |
| `--token2wav-scheduler` | `deadline` | `legacy` is retained for compatibility and ablation |
| `--token2wav-deadline-reserve-ms` | `100` | Protection window as the playback buffer approaches empty |
| `--speech-token-chunk-size` | `15` | Speech tokens in the first streaming hop |
| `--speech-token-chunk-growth` | `2` | Growth multiplier for later hops; use `1` for a fixed shape |
| `--streaming-cuda-graph` | disabled | Enable streaming Flow and HiFT CUDA Graphs with built-in buckets |
| `--speaker-encoder-tensorrt` | disabled | Run the CampPlus speaker encoder with TensorRT |
| `--trim-leading-silence` | disabled | Modify the beginning of the PCM stream to reduce audible TTFA |

Display the complete CLI help:

```bash
uv run --frozen faster-cosyvoice-server --help
uv run --frozen python examples/offline_inference.py --help
```
